# Music Player リニューアル設計

## 目的

音楽ファイルを開いた直後から、現在の曲、再生操作、次に再生する曲が迷わず把握できるプレイヤーにする。スマートフォンと iPad の縦横表示、キーボード操作、iOS Safari のバックグラウンド再生を同じ機能として扱う。

## 今回実装する基盤

- 濃紺と Comistream ブルーを基調にした、カバーアート中心の再生画面
- スマートフォン縦向きと狭い iPad 縦向きは上下配置、スマートフォン横向きと iPad 横向き、デスクトップは再生画面と再生リストの 2 カラム
- `safe-area-inset-*` と動的 viewport による Safari のアドレスバー、ホームインジケータ、ノッチへの対応
- 44px 以上を基本とするタップ領域、明確なフォーカス表示、状態を伝える `aria-label` / `aria-pressed`
- クリック、ドラッグ、矢印キーで操作できる再生位置スライダー
- 再生リストを常時表示し、現在曲、曲数、ファイル形式を見分けられる構成
- アルバムアート上だけで有効になる左右スワイプ。ページスクロールや音量操作との誤反応を避ける
- `prompt` / `alert` を使わないプレイリスト作成・追加ダイアログと、画面内ステータス表示
- 曲を連続して切り替えた場合も、古いメタデータやカバー画像を現在曲へ表示しないリクエスト制御
- M4A / ALAC の階層化された atom とファイル末尾の `moov` から、タイトル、アーティスト、埋め込みカバーを取得

## 画面構成

### スマートフォン縦向き

1. ブランドと現在再生中の位置
2. カバーアート、曲名、アーティスト
3. 再生位置と主要コントロール
4. 音量、ダウンロード
5. 再生リストとプレイリスト操作

縦スクロールを許可する。Safari の表示領域が変化しても、操作部を画面外へ固定しない。

### スマートフォン横向き

左に再生画面、右に再生リストを置く。高さを抑えるため、左側は小さいカバーアートと曲情報を横並びにする。主要操作は常に 1 行に収める。

### iPad 縦向き

狭いモデルでは上下配置にし、各領域の横幅を十分に確保する。広いモデルでは 2 カラムに切り替える。

### iPad 横向き

左に再生画面、右にスクロール可能な再生リストを置く。ページ全体のスクロールとリスト内スクロールを分離する。

## 操作モデル

- 再生、一時停止、前後の曲、シャッフル、リピートは中央の主要操作として扱う。
- 再生位置は操作中の時間を即時表示し、操作確定時に音源へ反映する。
- キーボードは、入力欄やダイアログにフォーカスがない場合だけ `Space`、矢印キーを受け付ける。
- iOS / iPadOS では音量UIを表示せず、端末標準の音量操作に任せる。
- エラーや保存結果は画面内へ表示し、連続操作を中断するモーダル通知を使わない。

## 追加機能の優先順位

### Phase 1: 信頼性とプレイリスト完成

最初に入れる機能群。現在ある API と UI の不足を埋める。

- 再生位置、音量、シャッフル、リピートの端末内保存と復元
- プレイリストの表示、名称変更、削除
- プレイリスト内の並べ替え、曲の削除、重複追加の確認
- 最後に再生した曲と位置からの再開
- サーバー側の共通パス解決処理。`realpath` で共有フォルダ配下に限定し、各 API で同じ検証を行う
- API の JSON 応答形式、HTTP ステータス、`Content-Type` の統一

完了条件は、再読み込み後に状態が復元され、プレイリストの作成から編集・再生・削除までを画面内だけで完了できること。

### Phase 2: 大規模ライブラリの操作

- 再生リスト内の曲名検索と絞り込み
- アーティスト、アルバム、フォルダ単位の一覧
- お気に入りと最近再生した曲
- 「次に再生」と再生キューの編集
- 曲数が多いフォルダ向けの段階描画

音源一覧 API は、ページング、自然順ソート、検索条件を受け取り、表示に必要なメタデータをまとめて返す。カバー画像は個別取得を維持し、遅延読み込みする。

### Phase 3: 再生体験

- スリープタイマー
- ReplayGain 対応音源の音量正規化
- 対応ブラウザでのギャップレス再生
- 歌詞ファイルの表示
- PWA のオフライン保存

ギャップレス、音量正規化、オフライン保存はブラウザ差とストレージ容量の影響が大きいため、機能検出と明示的な設定を前提にする。音源の自動ダウンロードは行わない。

## データと API の方向性

プレイリスト曲には一意な ID を持たせ、並べ替えと削除をファイルパスから切り離す。将来追加する主な操作は次のとおり。

| 操作 | メソッド | 主な入力 | 主な出力 |
| --- | --- | --- | --- |
| プレイリスト更新 | POST | ID、名称、説明 | 更新結果 |
| プレイリスト削除 | POST | ID | 削除結果 |
| 曲の並べ替え | POST | プレイリスト ID、曲 ID の配列 | 更新結果 |
| 曲の削除 | POST | プレイリスト ID、曲 ID | 削除結果 |
| ライブラリ検索 | GET | query、cursor、sort | 曲一覧、次 cursor |

変更系 API には既存のセッション認証と CSRF 対策を適用し、ユーザーが所有するプレイリストだけを更新する。DB の複数行更新はトランザクションで処理する。

## 実装構成

現在は PHP が HTML と CSS を生成している。Phase 1 で動作を安定させた後、次の単位へ分離する。

- `music_player.php`: 入力検証、HTML シェル、JSON API
- `music_player.css`: レスポンシブレイアウトと表示状態
- `music_player.js`: 再生状態、キュー、ダイアログ、Media Session
- 音声パス解決ヘルパー: 共有フォルダ境界と形式検証

フレームワークや外部 CDN は追加せず、既存の配布方法を維持する。

サーバー側の互換性基準は、AlmaLinux 10 の標準環境に合わせて PHP 8.3 とする。Ubuntu Server 26.04 の PHP 8.5 でも同じコードを使用し、PHP 8.3より新しい構文や関数には依存しない。

## 検証計画

- 代表 viewport: 390×844、844×390、768×1024、1024×768
- 最小幅 320px、長い日本語ファイル名、0 曲、1 曲、1000 曲
- タップ、ドラッグ、キーボード、VoiceOver のフォーカス順
- 回転、Safari のアドレスバー伸縮、ホーム画面追加時の safe area
- 再生中の画面ロック、バックグラウンド移行、イヤホン操作、割り込み復帰
- メタデータなし、カバーなし、遅い応答、未対応形式、通信切断

自動テストでは viewport ごとのはみ出し、主要ボタンの操作面積、選択曲の更新、シーク、ダイアログ送信を確認する。iOS の音量とバックグラウンド再生は実機試験を受け入れ条件にする。
